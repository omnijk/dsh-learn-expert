# 摸底诊断出题要求

目标：测学习者的**真实理解深度**，不是考背诵。3–5 题，由浅到深。

## 出题原则

- 探测式：要求判断、推演、举例、比较，而不是回忆定义。
- 情境化：给一个具体场景/代码片段/反例，问"会怎样""为什么""哪里有问题"。
- 分层：第 1 题测直觉（听说过没有），中间题测机制理解，最后 1–2 题测边界与迁移。
- 针对性：先读画像（`ai_learn_profile_get`），对历史高频错因（errorPatterns 计数高的类别）专门出一题探测。

## 呈现方式（重要）

- **一次 `ask_user_question` 调用把 3–5 题批量发出**，禁止"问一题 → 等回答 → 再问下一题"。
- 答案可枚举的题做成选项卡：选项 = 正确理解 / 1–2 个典型误解 / 部分正确 / **"不知道，没接触过"**（每题必有兜底项）。学习者可用自定义输入补充。
- 选项顺序随机化，不要把正确项固定在第一位；选项措辞不暗示对错。
- 必须自由表达才能测出深度的题（讲思路、举例）保留为开放题，附在同一条消息末尾，一条消息给全。
- 学习者跳过某题 = 该题按"不知道"处理，估计从低，不就同一题追问第二次。
- 诊断是"了解起点"，不是考试：开场只需一句暖场（"为了给你挑个合适的起点，先快速了解几个问题，点一点就行"），不解释流程、不念规则。

## 质量检查清单（出题后逐条自查）

- [ ] 没有任何一题能用"背下来的定义"直接回答。
- [ ] 每题都有"不知道/不确定"兜底选项，降低胡编动机。
- [ ] 没有一题暗示答案（避免"是不是因为 X 所以 Y"式引导；选项措辞中立）。
- [ ] 题目覆盖主题的主要前置概念，能支撑每个候选节点的掌握估计。
- [ ] 禁止出现"请背诵""请定义""请默写"类指令。
- [ ] 所有题目在一次提问中发完，没有逐题挤牙膏。

## 判定与输出

- 根据回答为每个候选概念给出 0–100 的估计掌握度，`evidence` 引用学习者原话（选项卡作答记录所选选项的原文）。
- 选项题全对但疑似蒙对时，就个别疑点追加一轮"为什么/举个例"的自由追问，再定估计，不重走全部题目。
- 建议起点 = 第一个估计掌握度 <80 的节点。
- 学习者全程答不上 ≠ 失败：起点设为零基础节点即可，这正是路线图存在的意义。
